= VERNICHTUNG USER MANUAL

== NAME
*Vernichtung* — A clean-room, limit-removing drop-in replacement software engine for classic 2.5D WAD games.

== SYNOPSIS
[subs="quotes"]
----
*vernichtung* *-iwad* _<BASE_WAD>_ [*-file* _<MOD_WAD>..._] [*-soundfont* _<SF2_FILE>_]
----

== DESCRIPTION
*vernichtung* is a clean-room, reverse-engineered 2.5D software game engine built completely from scratch in portable C and SDL2.

Unlike traditional source ports that fork the historical 1997 id Software source tree, *Vernichtung* was developed purely from public layout specifications and structural documentation. This provides a legally unencumbered, binary-compatible runtime tool environment released under the permissive *3-Clause BSD License*.

The engine delivers a highly faithful emulation of classic 1993–1994 gameplay parameters (enforcing the authentic 35Hz simulation timing clock grid, player momentum matrices, and continuous flat visplane row-casting) while actively stripping away legacy engine overflows:

* *No Visplane Crashes* — Dynamic allocation arrays replace rigid static bounds buffers, ensuring massive community map architectures do not crash the runtime engine.
* *Hardened Boundary Defenses* — Direct memory loader operations validate stream structures, neutralizing corrupt or malformed asset entries before they damage the heap context.
* *Dynamic Library Firewalls* — Heavy audio synthesis frameworks (like FluidSynth) are unmapped from compile-time link matrices, isolation-loaded via `dlopen` or `LoadLibraryA` runtime handles to preserve downstream software freedom.

* *It basically Crispy Doom limit-removing but with Chocolate Doom gameplay and visuals, physics, etc*

* *See PHILOSOPHY for more infomation*

== OPTIONS (AS FOR NOW)
*-iwad* _<BASE_WAD>_::
Specifies the primary, standalone internal game asset base file (e.g., `freedoom2.wad`). This engine scanning layer verifies that the archive starts with explicit "IWAD" binary signature markers before initializing memory structures. This parameter is mandatory.

*-file* _<MOD_WAD>..._::
Appends one or more custom patch assets or level expansion files (PWADs) sequentially into the engine's master global index dictionary map layout. Records loaded from subsequent archives override duplicate stock base game assets using a reverse-priority lookup queue, making it a seamless drop-in tool for community modifications.

*-soundfont* _<SF2_FILE>_::
Forces the runtime dynamic synth tracking layers to load an explicit external SF2 instrument pack layout patch profile (such as a _Roland SC-55_ soundfont) into the synthesizer matrix context, overriding default operating system backend sound definitions.

== EXIT STATUS
*0*::
Success. The engine loop winddown sequences terminated without exceptions.

*1*::
Failure. A structural asset parameter was missing or memory alignment checks encountered fatal issues.

== BUGS
The engine software rasterizer is currently affected by a non-linear vertical perspective projection texturing column interpolation scale distortion. Walls may display elastic stretching scaling behaviors when inspected closely or during rapid camera rotation frames. Floor and ceiling flat visplanes map rock-solidly and are completely unaffected.
